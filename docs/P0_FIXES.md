## 1. Silent data loss (`findoclens/backends/native_grid.py`, `findoclens/coverage.py`, `findoclens/router.py`, `adapters/canonical.py`)
Cause (confirmed in code): `read_words()` excluded every bare 1900–2099 integer from the numeric tokens, before the unassigned-token audit; the table seed needed ≥ 2
numeric columns; `unassigned_numeric_tokens` was info-level; the router only looked at labels/absent cells.
* **Year-like integers are numeric first** and are demoted to header text only by structure: the first row of a table whose only numerics are bare years is a period header
  if it has no label (a unit note is not a label; a data row always has a label); a labelled row under a real header line ("2025/3", "当期") is a body row; a labelled
  year-only first row with no header line above ("科目 2025 2026") cannot be decided from tokens and is **kept as data and flagged** `year_like_tokens_ambiguous`
  (warning → `partial`, `review_required`). Year-like tokens outside every table are page text.
* **One-column tables** (pass 1b): runs of ≥ 3 labelled single-value rows in one column at regular pitch that are not inside the body of a table already found; row inside a wider
  table stays that table's partial row. Tested beside (right), left of and below a 2-column table. Flag `single_column_table_inferred` (info).
* **Completeness**: `unassigned_numeric_tokens` is a warning when tokens are table-like (inside a table footprint, a column stack, or sharing a row), info otherwise (page numbers,
  `- 4 -` footers); it lists token text + box. `findoclens/coverage.py` reconciles the text layer's numeric tokens with the cells/headers of **any** backend's final prediction;
  the router applies it last and returns `needs_visual_review` + `source_numeric_tokens_not_in_output`. Canonical outputs carry `review_required` and `review_reasons`
  (the contract has no review status, so `partial` carries it).
* Effect on the existing corpus: **none** — across 144 backend/page cold predictions `p0fix2` vs `fin1` has 0 status changes, 0 changes of any value/alignment axis
  (`results/p0/fin1_vs_p0fix2.json`); the only extraction difference is label text of 0-cell rows in an abstained Docling cm=False Daiwabo output (see §5). The fixes matter for inputs the corpus did not contain.

Limits (not fixed): coverage needs a text layer (raster pages: the OCR branch already withholds success); a year demoted to header text by a header-looking context is covered
by a header box, so reconciliation cannot catch that mistake; left-aligned layouts still produce `unit_not_detected` (a pre-existing window limit; the year-amount control is `partial` for that reason);
the 3-row minimum means a 2-row one-column table is reported (warning), not extracted.

## 2. Evaluator (`benchmark/evaluate.py`, version 2 — stored in every new report as `evaluator_version`)
* New separate axes (denominators are all gold numeric cells, so a missing cell earns nothing on any of them): `cell_period_accuracy`, `cell_role_accuracy`,
  `cell_header_link_accuracy` (the predicted cell's `header_id` must resolve to a leaf header on the same physical column as the gold cell's header; ID spelling is irrelevant),
  `cell_structure_exact` (period ∧ role ∧ link, value ignored), `cell_evidence_localization` (IoU ≥ 0.3 with the gold evidence box; threshold chosen by me, not validated).
  Value fidelity (`numeric_*`), alignment (`cell_coverage`, rows/tables), completeness (`missing_cells`, `silent_omission_rate`) and hierarchy keep their definitions.
* **Omission warnings are scoped**: only run-level failure statuses/codes cover everything; `partial_data_row`/`omitted_*`/`unassigned_numeric_tokens`/… cover a gold cell only
  through its row label, a box overlapping the gold cell, or by being attached to the matched row. Unlocated, unlabelled ones cover nothing and are counted (`unscoped_omission_warnings`).
* Predicted headers of unmatched (extra) tables count against header precision; `false_assurance` (success status only) now also fires on cell-structure errors, extra headers, row-order errors
  and misleading evidence boxes, and reports `false_assurance_reasons`.
* Evidence (`docs/P0_BEFORE_AFTER.md`, finding 2): the pre-fix evaluator is loaded verbatim from `git show 90f5e50:benchmark/evaluate.py`.
* Re-scoring the **stored** `fin1` predictions with v2 (`results/p0/rescored_fin1.json`, nothing re-extracted): value axes unchanged on all 144 pages, `false_assurance` 0 → 0 and silent omissions
  identical for every backend. So the blind spots were real but not exploited by the reported runs; what changed is that periods/roles/links are now measured at all. New measured weakness
  it exposed: Daiwabo cell periods were **34/63** for `native_grid` (63/63 on values) — see §5.
* Not done: no TEDS/GriTS; row-level (not cell-level) omission flags for row-scoped warnings; the table IoU threshold remains 0.1.

## 3. Merged cells (`findoclens/backends/docling_backend.py`, `adapters/canonical.py`)
* Body label merged over rows: covered rows inherit the label text as `label`, `raw_label` stays null (not printed there), table warning `body_rowspan_label_inherited` with the row indices.
* Merged numeric body cell (rows or columns): the value stays in its first slot, covered slots stay `absent_text_cell` (never copied), warning `body_cell_span_unsupported`; columns covered by a merged numeric cell
  count as data columns so the table does not silently shrink.
* Header groups over the same column set nest by header row (outer → year → leaf); header `rowspan` is preserved. A vertically merged leaf header keeps its group parent (this already worked; now tested).
* Bug I introduced and fixed in the same pass: a label merged across two *label columns* was duplicated (`借入金借入金`), caught on the Docling cm=False Daiwabo re-run; regression test added; that one page was re-run as `p0fix3_main` (abstained, 0 cells; the `p0fix2` copy still shows the duplication in 0-cell rows and is kept).
* Not done: no real page with merged cells exists in the corpus; mapper behaviour is verified on synthetic Docling-shaped grids only. A body row-spanned *numeric* cell is flagged, not supported.
